# hdmi-defubar: design

Date: 2026-07-24
Status: approved

## Problem

On this MacBook Pro (M1 Pro, macOS 15.6), externally connected HDMI monitors frequently
come up with default resolution and arrangement instead of the previously configured
layout, forcing manual reconfiguration of a two-external-monitor setup.

Root cause (verified on this machine): macOS keys display configurations on a display
UUID derived from the monitor's EDID. When it cannot derive a stable UUID it generates
a random v4 UUID at connect time. The ByHost WindowServer plist
(`~/Library/Preferences/ByHost/com.apple.windowserver.displays.<host>.plist`) contains
236 stored configs referencing 127 distinct display UUIDs; the built-in display's
stable UUID appears 153 times while 83 of the UUIDs appear at most twice. Both current
external displays (LG HDR 4K and Samsung Odyssey G70B) carry random v4 UUIDs that each
appear exactly once in the history. Every connect with a fresh UUID is treated as a
never-seen monitor and gets a default config.

Meanwhile CoreGraphics reports a stable hardware identity for both monitors regardless
of UUID churn:

- LG HDR 4K: vendor 7789, model 30471, serial 502218
- Odyssey G70B: vendor 19501, model 29233, serial 1536

## Solution overview

A macOS menubar app that recognizes monitors by stable hardware fingerprint
(vendor, model, serial) instead of the churned UUID, remembers the desired layout per
set of connected monitors and reapplies it automatically when macOS assigns a new ID
and falls back to defaults. It shows a system notification when it intervenes so the
fix is visible but requires no action.

Form factor: SwiftUI `MenuBarExtra` app, `LSUIElement` (no dock icon), launch at
login via `SMAppService`.

## Components

### Display watcher

- Registers `CGDisplayRegisterReconfigurationCallback`.
- Reconfiguration events arrive in bursts during connect/disconnect; the watcher
  debounces with a settle window (about 2 seconds) before classifying and acting.
- Classifies each settled event as either a topology change (display added or
  removed) or an in-place configuration change (same displays, different mode,
  origin or main display).
- Ignores events generated by the app's own restore operations (a flag is set for
  the duration of an apply plus settle window).

### Fingerprinting

- Per display: `CGDisplayVendorNumber`, `CGDisplayModelNumber`,
  `CGDisplaySerialNumber` plus a builtin flag.
- If serial is 0 or unavailable, the fingerprint falls back to vendor + model.
  Two identical monitors with no serial are matched in a stable but arbitrary
  order (documented limitation).
- A layout is keyed by the set fingerprint: the sorted multiset of display
  fingerprints currently online. Laptop-alone, laptop+LG, laptop+both and any
  other combination each get their own saved layout.

### Layout store

- JSON file in `~/Library/Application Support/hdmi-defubar/layouts.json`.
- Maps set fingerprint to a layout: for each display fingerprint, the desired
  resolution (pixel width/height), scale factor, refresh rate, origin in global
  space and whether it is the main display.
- Atomic writes (write temp file, rename). Corrupt or unreadable store is
  renamed aside and treated as empty, with a notification.

### Restorer

- Triggered after a settled topology change.
- Looks up the layout for the current set fingerprint. No entry: do nothing
  (the learner will create one once the user arranges displays).
- Diffs saved layout against current state. No differences: do nothing.
- Applies differences in one transaction: `CGBeginDisplayConfiguration`,
  `CGConfigureDisplayWithDisplayMode` (mode selected from
  `CGDisplayCopyAllDisplayModes` including HiDPI modes via
  `kCGDisplayShowDuplicateLowResolutionModes`), `CGConfigureDisplayOrigin`,
  `CGCompleteDisplayConfiguration` with `.permanently`.
- Main display is expressed through origins (main display at 0,0), matching how
  CoreGraphics models arrangement.
- If the exact saved mode is not offered (a monitor can expose different mode
  lists per port), the closest mode with the same point size is chosen and the
  notification mentions the substitution.
- At most one restore attempt per settled connect event; if the result still
  mismatches, notify and stop. No retry loops.
- Posts a user notification on intervention, for example:
  "Odyssey G70B reconnected with a new display ID; restored your layout."

### Learner

- Triggered after a settled in-place configuration change not caused by the app.
- Waits for about 10 seconds of stability, then snapshots the current state as
  the desired layout for the current set fingerprint (auto-learn: the last
  arrangement made by hand wins).
- Never learns from topology-change events; those are exactly the moments when
  macOS has just applied a wrong default.
- "Save current layout" in the menubar performs the same snapshot explicitly at
  any time.

### Menubar UI

- Status: connected monitors (names and fingerprints), whether a saved layout
  matched, last action taken with timestamp.
- Actions: Save current layout, Restore now, Pause/resume automatic handling,
  Launch at login toggle, saved layout list with delete.

### Notifications and logging

- `UNUserNotificationCenter` for user-visible interventions and errors.
- `os.log` (subsystem `dk.ulrik.hdmi-defubar`) for all decisions: event
  classification, fingerprints seen, diffs computed, modes chosen, apply results.

## Out of scope for v1

- Rotation (requires private IOKit API; both current monitors are landscape).
- Mirroring configurations.
- Window placement (Stay already handles windows).
- EDID overrides or other root-cause fixes (largely ignored on Apple Silicon).

## Error handling summary

- Mode not found: closest same-point-size mode, notify.
- Apply failure (`CGError` non-success): abort transaction, notify with error.
- Corrupt store: rename aside, start empty, notify.
- Notification permission denied: continue silently, log only.
- Restore is capped at one attempt per connect event.

## Build, packaging and testing

- Swift Package with an executable target; a build script wraps the binary into
  `hdmi-defubar.app` with an Info.plist (`LSUIElement` true, bundle id
  `dk.ulrik.hdmi-defubar`) since notifications and login-item registration
  require a real bundle.
- Unit tests (XCTest via SwiftPM) for fingerprinting, set-fingerprint keying,
  layout diffing and the store round-trip. Display manipulation is exercised via
  a documented manual test procedure (unplug/replug HDMI, verify restore and
  notification) since it cannot run headless.
- A `--dump` CLI flag prints current displays, fingerprints and the matched
  layout as JSON for debugging.

## Known limitations

- Fingerprint matching carries all identity weight; two identical serial-less
  monitors cannot be told apart reliably.
- If macOS itself restores a correct layout (UUID happened to be stable), the
  app does nothing; it only intervenes on mismatch.
